# FIXED554 バグ修正記録

## 1. 原因の特定

### PDF出力の非同期処理

ShiftStore.exportShiftPDFAsyncは、キャッシュキーを作った後で共有タスクの結果をawaitしていた。MainActorはawait中に店舗切替・データ更新を受け付ける。復帰後に状態を再確認しないため、成功時には旧データのPDFを返し、失敗時には旧キーと新しいスナップショットを組み合わせて再生成できた。新規生成待ち後にも検証がなかった。OutputViewには独自の検証があったが、サービス側の他の呼出元には同じ保証がなかった。

### 表示中のPDFの陳腐化

OutputViewは設定・店舗変更でプレビューを無効化していたが、データ版変更は監視していなかった。シフトやスタッフ情報などが更新されても、表示中のPDFは古い内容のまま残った。

## 2. 修正のポイント

- キャッシュ待ちと新規生成待ちの両方で、キャンセル・書込禁止・店舗ID・データ版を再検証し、不一致時はnilを返す。
- 他の呼出元も使う共有生成タスクはキャンセルしない。
- データ版変更時に既存のプレビュー破棄処理を実行し、古いPDFを閉じる。
- 実際のサービスメソッドに対し、キャッシュ成功・データ更新・生成失敗後の更新・店舗切替・キャンセル・書込禁止・新規生成など10ケースを検証する。

実画面の表示確認は未実施。
