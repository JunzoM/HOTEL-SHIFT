# FIXED557 全体セルフレビュー

## 点検範囲

起動時ロード、保存保護、バックアップ復元と共有スナップショット検証、保存チケット、Cloud同期の競合制御、シフト編集・勤務パターン・索引、PDF生成、CSV出力、直近の画面切替設定と最適化を点検した。実機UI操作と実CloudKit接続は未確認。

## 1. 原因の特定

1. バックアップ検証はID・店舗・時給などの整合性を確認していたが、シフトの日付・勤務時刻・休憩時刻、スタッフの在籍期間、パターンの時刻・有効期間の検証が不足していた。Int.maxなどを通すと後の時刻演算で整数オーバーフローの可能性がある。開始時刻だけの旧形式では、標準終了時刻より後の開始も受け入れていた。
2. 通常シフトCSVはスタッフの現在時給を使っていた。シフトに記録した過去時給と、人件費計算・人件費CSVの適用時給とが一致しなかった。
3. CSVのカスタム終了時刻は24時間の剰余だけを書き出し、翌日の情報を失っていた。翌朝6時が06:00だけになり、標準夜勤の「翌9:00」とも不一致だった。

## 2. 修正のポイント

- 共通の分数検証を追加し、値の範囲を確認してから加減算する。復元・勤務パターン保存・グリッド一括編集へ適用。休憩位置はend-restで比較し、restStart+restのオーバーフローを避ける。
- 旧形式の一部時刻だけの指定は標準勤務時刻と組み合わせて検証し、安全な旧データは受け入れる。
- 日付は厳密にyyyy-MM-ddへ往復変換して確認する。ユニークな日付だけを解析するため、54万件すべてに対する重複したDateFormatter呼出を避ける。
- 勤務パターンの名前・基本区分・期間限定の開始終了、在籍期間も確認する。不正データは復元前に拒否する。既存の元ファイル保護処理は維持。
- CSVはhourlyWageSnapshotを優先し、旧シフトに記録がなければ現在時給を使う。時給0も正しく扱う。
- CSVの終了時刻が1440分以降の場合は翌を付け、深夜0時も翌00:00にする。

- CSV：過去時給、旧形式フォールバック、時給0、翌朝・翌0時、引用符・改行、保存保護。
