# FIXED561 全体改善（性能・安定性・体験）

## 1. 性能：1セル操作の全件走査を索引照会へ

548,000行規模では、1セルの編集でも全シフトを先頭から探す処理が残っていた。既存の `ShiftLookupIndex` は同じ「最初の1行」を保持しているため、結果を変えずに置換した。

| 処理 | 変更前 | 変更後 |
| --- | --- | --- |
| `setShift` / `setShiftTimes`（シフト編集・時刻スライダー） | 全シフト `firstIndex` O(N) | セル索引 O(1) |
| `applyDayTimeline` / `restoreDayTimeline`（日別バー編集・取消） | 全シフト走査＋選択店舗の申請配列生成 | セル索引＋申請セル索引 |
| `applyStaffPersonalTime`（個人時間の適用） | 全シフト `indices.filter` | 対象日の位置のみ |
| `clearShift` | 全件 `contains`＋`removeAll` の2回走査 | 対象日の位置で判定し1回の再構築 |
| `approvedLeaveShiftConflictDetails`（パターン画面を開くたび） | 全シフト走査 | 承認済み申請のセルのみ照会 |
| `applyPatternWithReport` | 全シフト・全申請から集合生成 | 適用期間（最大366日）の位置のみ |
| `staffDeletionImpact` | 全シフト走査 | 選択店舗の位置のみ |
| 希望休テキストの日付抽出 | 呼出ごとに正規表現をコンパイル | 1回だけコンパイル |

同一セルの重複行（旧データ）は従来どおり保存順の先頭を使用し、`clearShift` は全重複を削除する。重複一覧の並びは同日・同名で順序が不定だったため、スタッフIDを第3キーに追加。

## 2. 安定性

- **バックグラウンド保存**：iOSでアプリを閉じる時に全データを同期書込みしていた。大規模データではUIスレッドが長時間停止し、システムに強制終了される危険があった。`beginBackgroundTask` で時間を確保し、エンコードと書込みは既存の非同期保存（世代チケット付き）で行う。期限切れ直前や非同期保存が未完了の場合は従来の同期保存へフォールバック。アプリ終了（willTerminate）は従来どおり同期保存。Macのウィンドウ非アクティブ時も同じ経路でUI停止を回避。
- **一時ファイルの掃除**：PDF・CSV・申請JSON・バックアップの共有用ファイルは毎回一意名で一時フォルダに作られ、削除されていなかった。起動時に1日以上前の自アプリ一時ファイル（pdf/csv/json）を削除。Documents内の復元用ファイルは対象外。

## 3. iCloud同期

- 30秒ごとの自動同期で、毎回Apple Accountの確認に2回の通信をしていた。確認済みアカウントを10分間再利用し、`CKAccountChanged` 通知・未認証エラーで即座に破棄。共有作成と招待受諾では常に最新を確認。
- CloudKitの生のエラー文を、通信断・混雑・未サインイン・容量不足・共有削除・権限不足ごとの日本語の案内へ変更。「iPadの設定で」の文言を「端末の設定で」へ（iPhone・Macでも表示されるため）。
