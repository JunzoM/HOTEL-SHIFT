# FIXED504 性能・不具合監査

対象：画面・モデル・保存・CloudKit・画像・PDF/CSV・バックアップ/復元。2026年10月28日。

原因と、修正に伴って追加した保護を区別する。「非同期化に伴う」と記載した項目は、旧版に既に存在した競合として断定しない。

| 優先度 | 確認した原因 | 修正 |
|---|---|---|
| P0 | 横スクロールの位置をSwiftUI Stateへ毎フレーム通知し、表のホストrootViewを差し替え、layoutIfNeededも毎回呼ぶ | UIKitでヘッダーを直接追従。表示内容の世代が変わった場合だけ本文を差し替える |
| P0 | 日付セル・申請行からスタッフ／全履歴を反復検索 | 店舗・月・日・スタッフ／日付の索引。変更値だけの編集では索引を再構築せず、追加・削除・移動時は更新 |
| P0 | 写真を含む全JSONの自動保存をUIスレッドで行う | 値スナップショットを専用キューで変換・atomic保存。同じ世代の保存を共有。世代チケットで遅れて来た旧保存を拒否 |
| P0 | 非同期化に伴い、復元・終了時フラッシュと旧保存が競合する可能性 | 同じ保存キューと世代管理へ集約。復元中にローカル編集が発生したら適用を中止し、現在データを保持 |
| P1 | 起動時にJSON・写真Base64の復号・整合性検証・索引作成をUIスレッドで実行 | 読み込み表示を先に出し、バックグラウンドで準備。破損ファイルの復旧保護を維持 |
| P1 | 顔写真にもカメラ元サイズを展開し、写真本体をキャッシュキーとして保持・比較 | ImageIOによる128px一覧サムネイル。非同期読込。SHA-256の小さなキーと32MB上限の画像キャッシュ |
| P1 | スタッフ編集中に写真を毎回Base64へ変換して未保存判定 | 変更前のData参照との比較へ変更。写真を文字列として複製しない |
| P1 | ホテル写真・ロゴの登録サイズが無制限、表示ごとに大きなBase64の指紋を計算 | 登録時に背景処理で上限サイズへ縮小。直近の表示画像を再利用。古い写真も表示時に縮小 |

| P1 | 連続編集を2秒間隔で全体送信、同期の安全コピーが無制限に増える | 5秒のまとめ送信。新しく作る通常の自動同期コピーは直近3個。利用者が選ぶ競合解決・手動復元のコピーは保持 |
| P1 | 希望休・人件費で同じ絞り込み・並べ替え・集計を何度も実行 | 画面ごとの上限付き世代キャッシュ。月別集計は索引から取得。申請行のスタッフ・シフトは直接参照 |

| P1 | バックアップ・復元も大きなJSONをUIスレッドで処理 | 準備・変換・読み書きを非同期化。処理中表示と二重操作防止。既存データを保管してから適用 |
| P1 | 勤務パターンの確認に、写真入り全JSONのコピーを都度作る | データ世代・店舗・期間の小さなトークンに変更。変更後の再確認を維持 |
| P2 | QRの画像とCIContextを表示ごとに作る | 上限付き画像キャッシュと共通CIContext。生成方式を維持（今回のシミュレータ読取りは未合格、結果表参照） |

## 維持するもの

保存データ・バックアップ・共有JSONの形式は変更しない。旧データの読み込み、承認済み希望休の保護、勤務時給履歴、復元前コピー、編集の競合確認、Undo/Redoを維持。既存PDFは背景レンダリングと同一条件の生成共有が実装済みで、その保護を維持する。

## 検証の範囲と残る制約

- 100人・6,100件と、100人分の写真を含むデータを測定する。さらに73,100件の履歴で索引の整合性を照合する。
- 最適化したMacの測定、iPadシミュレータ上のアプリコードの測定、画面の表示確認を区別する。物理iPadのFPS改善率として表示しない。
- CloudKitの変更タグによる不要なダウンロードは減らすが、変更送信は従来互換のデータ一式方式を維持する。大量写真の送信量を根本的に減らすには、共有フォーマットの移行と複数アカウントでの移行検証が別途必要。
- 実機2台・異なるApple Account間の招待／通信、実機のスワイプ追従・メモリ上限、物理プリンタはこの環境では検証できない。
- アプリがバックグラウンドへ移る際の最終フラッシュはデータ保全のため同期的に完了させる。通常の操作中の自動保存は非同期。前の古い保存が新しい保存を上書きすることは世代管理で防ぐ。

# FIXED504 修正・テスト結果

4店舗・100人・6,100件のシフトと100人分のJPEGを使って確認しました。保存形式は維持しています。原因別一覧は [監査リスト](#fixed504-audit)、生の測定値・条件は [検証記録](../reports/fixed504_validation.json) を参照してください。

## 測定結果

| 検証 | 修正前／比較実装 | 修正後 |
|---|---:|---:|
| 横スクロール中の最大フレーム間隔 | 416.0ms | 16.7ms |
| 同スクロール中25ms超のフレーム数 | 7回 | 0回 |
| 日付見出しの最大追従ずれ | 旧構造は数値取得対象外 | 0pt |
| 写真入りJSON保存中のUI処理の最大停止間隔 | 365.5ms | 6.5ms |
| 775セル検索（Mac最適化ビルド） | 29.59ms | 0.82ms |

スクロールは同じiPad Proシミュレータ・Debugビルド・同じ写真入りデータでFIXED503と504を比較し、UIKitのアニメーションをCADisplayLinkで測定しました。実機の指操作のFPSではありません。保存は504のテスト内で旧方式の同期JSON保存と新しい非同期保存を比較しました。保存処理自体は363.3ms→358.9msで、主な改善はUIスレッドを塞がないことです。写真入りJSONは約70MiBで、未変更の同期スナップショット20回取得は合計0.017msでした。

PDFは初回113.1ms、同条件の再取得0.31ms、CSVは19.4msでした。これは当該シミュレータ・データ・出力条件の値で、全端末の保証値ではありません。

## 合格した確認

- Debug／Releaseビルド、アプリ19ファイルのSwift構文確認。
- 11系統の既存・新規回帰スイート。日シフト、範囲編集・Undo、スタッフ情報、希望休、申請リンク、基本パターン、サンプル、同期判断・共有準備など。
- 索引を180回の追加・削除・並べ替え・値変更で全再構築結果と照合。73,100件の履歴でも整合性確認。
- 非同期保存の世代競合、古い保存の拒否、書込み失敗、復元前コピー、通常自動コピー3個保持、利用者が選ぶコピーの保持。
- 12MP写真の縮小、100人分の別JPEGとサムネイルキャッシュ、店舗間の参照分離。
- PDF／CSV、正常バックアップ復元、壊れた復元の拒否、読込み保護中の出力禁止。

## 残る範囲

- 物理iPadのスワイプ・メモリ上限・長期運用と、異なるApple Account間のCloudKit実通信は未検証です。
- 変更送信は互換性維持のため全データ方式です。大量写真の通信量削減には共有形式の移行が必要です。
- QRキャッシュの再利用は合格。今回のシミュレータではVisionの標準推論が起動できず、CPU代替のテスト画像も認識できなかったため、今回版のQR読取りを合格扱いにしていません。既存のリンク形式・QR生成方式は維持しています。
- 写真が多い起動直後や初回サムネイルには処理時間が残ります。裏側で実行することで操作中の停止を抑えています。

`fixed504_native_before_photo_key_fix.json`は504開発途中の画像キー調査記録であり、FIXED503との比較値ではありません。検証用の写真入り実データとプレビュー起動コードは製品へ含めていません。README.mdは1本です。
